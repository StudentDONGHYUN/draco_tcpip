# 실행 결과 템플릿 (Reports)

Spec-Driven 흐름에 맞춘 실행 보고서 템플릿입니다. 실행마다 **품질 특성 점수**(기능성·정확도·성능·확장성·신뢰성·운영 가능성·보안성·사용성·테스트 가능성·이식성·유지보수성)를 균형 있게 확보하도록 설계했습니다. 모든 섹션은 비워두지 말고, 해당 사항이 없으면 `N/A`로 표기합니다. 품질 특성 설명과 예시 증거는 [`Quality_Attributes_Catalog`](../reference/Quality_Attributes_Catalog.md)에서 확인하세요.

## 1. 메타데이터
| 키 | 값 | 비고 |
| --- | --- | --- |
| `run_id` | `demo_run_2025-03-20` | 실행을 고유하게 식별하는 ID(디렉터리 이름과 일치) |
| `profile` | `client.profile.yaml` | 사용한 레이아웃/네트워크/SLAM 프로파일 |
| `topics` | `/sensing/lidar/top/pointcloud` | 주요 ROS 토픽 목록 |
| `bag` | `/data/bags/sample.db3` | 입력 rosbag 경로(없으면 `live`) |
| `commit` | `abcdef1` | 실행 시점 git 커밋 SHA |
| `artifacts_root` | `data/results/<run_id>/` | `artifacts/`, `metrics/`, `ros_logs/`가 포함된 루트 |
| `report_version` | `1` | 결과 템플릿 스키마 버전 |

## 2. 환경 및 구성
- **하드웨어**: CPU/코어, RAM, GPU, 네트워크 인터페이스, MTU
- **소프트웨어**: OS, 커널, ROS 2 배포판, Python 버전, Draco 인코더/디코더 빌드
- **구성 해시**: `configs/` 혹은 프로파일 파일의 git SHA 또는 파일 체크섬
- **실행 명령**: `stream_server`, `stream_client`, 런치 또는 스크립트 전체 명령어 블록
- **네트워크 에뮬레이션**: 적용한 netem 프로파일과 파라미터(`delay`, `loss`, `rate` 등)

## 4. 핵심 결과 요약
- **지연**: p50/p95/p99, 최대치, 계산 방법(예: `metrics/latency.csv` 기준)
- **품질**: Chamfer 추정치, 최근접 평균 상대 오차, 점수 카디널리티 등 핵심 지표
- **트래픽**: 전송된 총 바이트, 평균/최대 in-flight 프레임 수
- **리소스**: CPU/GPU 사용률, 메모리/디스크 스파이크, 스레드/프로세스 수

## 6. 재현 절차 (필수)
1. 환경 준비 명령어 (venv, ROS 2, rosdep 등)
2. netem 적용 또는 초기화 명령어
3. 서버/클라이언트/런치 실행 명령어
4. 로그·아티팩트 수집 명령어
5. 품질 리포트 필터링 명령어(`jq`, `pandas` 등)
