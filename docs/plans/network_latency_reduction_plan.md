# 네트워크 왕복 지연 최소화 개선 계획

## 목표
- Draco로 압축된 포인트클라우드 프레임을 스트리밍 클라이언트와 서버 사이에서 주고받을 때 엔드투엔드 왕복 지연을 가능한 한 줄입니다.
- ROS 2와 TCP/IP가 혼재된 환경에서 결정성을 해치지 않으면서 처리량을 높입니다.
- 데이터 흐름 아키텍처, 네트워크 프로토콜, 구현 언어(C++ 전환 포함)를 모두 다루는 단계별 로드맵을 제공합니다.

## 현재 제약과 관찰 사항
- ROS 2 파이썬 노드는 GIL의 영향으로 동시 메시지 처리가 제한되고, 직렬화나 서브프로세스 조율이 집중될 때 지터가 발생합니다.
- 현재 TCP 전송은 프레임 전송과 응답 수신을 순차적으로 처리해 파이프라이닝이 제한되고, 인코딩·네트워크·디코딩 단계 간 중첩이 줄어듭니다.
- 파이프라인이 외부 Draco 인코더/디코더 바이너리에 의존하며, 디스크 기반 스풀링(rosbag→PLY)이 추가 I/O 지연을 만들어냅니다.
- 프레임별 지연을 구성 요소(인코딩, 네트워크, 디코딩, 퍼블리시) 단위로 관측할 수 있는 계측이 부족합니다.

## 개선 과제

### 1. 아키텍처 파이프라인 고도화
- **비동기 프레임 파이프라인 도입**: 캡처, 인코딩, 전송, 디코딩 단계를 유한 큐와 역압 신호를 갖춘 이벤트 기반 아키텍처로 전환합니다. Python에서는 `asyncio`, C++에서는 `rclcpp` 실행기를 활용해 각 단계를 동시에 처리합니다.
  - ✅ `../designs/async_pipeline_design.md`에 큐 용량, 장애 처리, 시퀀스 다이어그램을 포함한 설계를 정리했습니다.
- **제로-카피 프레임 전송**: 공유 메모리나 메모리 맵 버퍼로 중간 디스크 쓰기를 대체하고, ROS 2 대여 메시지를 통해 PLY 프레임을 전달합니다.
  - ✅ `stream_client.py`와 `bag_recorder` 경로에 공유 메모리 백엔드를 추가해 디스크 스풀을 거치지 않고 프레임을 공급합니다.【F:ros2_ws/src/draco_roundtrip/draco_roundtrip/nodes/stream_client.py†L1-L222】
- **프레임 배칭 및 우선순위 채널**: 작은 프레임을 상황에 따라 묶어 보내고, 중요 프레임에 우선순위 경로를 부여해 제어 오버헤드를 줄이면서 핵심 업데이트는 보장합니다.
  - 🟡 `stream_client.py`에 우선순위 큐와 인플라이트 한계 기반 역압을 적용했으며, 프레임 배칭은 후속 실험으로 남겨둡니다.

### 2. 네트워크 프로토콜 및 전송 개선
- **바이너리 프레이밍 프로토콜**: JSON 제어 메시지를 구조체 기반의 컴팩트한 바이너리 헤더로 교체해 파싱 오버헤드와 페이로드 크기를 줄입니다.
  - ✅ `stream_client.py`와 `stream_server.py`에 선택 가능한 `binary` 프로토콜을 추가해 왕복 syscalls을 줄였습니다.【F:ros2_ws/src/draco_roundtrip/draco_roundtrip/utils/stream_protocol.py†L1-L120】
- **지속 연결 다중화**: 제어/데이터 채널을 하나의 TCP 연결에서 다중화하거나, 손실과 지연에 강한 QUIC을 도입해 핸드셰이크 지연을 줄이고 혼잡 제어를 내장합니다.
- **선택적 UDP/QUIC 고속 경로**: FEC(Forward Error Correction)를 포함한 UDP 기반 전송을 실험해 손실이 허용되는 환경에서 재전송으로 인한 지연 스파이크를 최소화합니다.
- **동적 MTU 튜닝**: PMTU 탐지를 구현하고 소켓 송수신 버퍼 크기를 조정해 고대역 링크에서 단편화 없이 최대 처리량을 확보합니다.

### 3. C++ 기반 구현으로의 전환
- **핵심 ROS 노드 C++ 이식**: `stream_client.py`와 `stream_server.py`를 `rclcpp` 노드로 포팅해 파이썬 GIL을 제거하고 결정적인 실행기 스케줄링을 확보합니다.
- **네이티브 Draco 연동**: 외부 바이너리를 호출하는 대신 Draco C++ API를 직접 사용해 메모리 내에서 인코딩/디코딩을 수행하고 서브프로세스 오버헤드를 제거합니다.
- **C++ 비동기 IO 활용**: Boost.Asio 또는 `std::async` 기반 논블로킹 소켓 처리를 통해 파이썬↔C++ 프로세스 전환 비용을 줄입니다.

### 4. 성능 계측과 피드백 체계
- **정밀 텔레메트리 구축**: `stream_client`/`stream_server`에 추가된 텔레메트리 로그를 확장하고, LTTng 또는 `ros2_tracing`을 활용해 캡처 → 인코딩 → 네트워크 전송 → 디코딩 → 퍼블리시 단계별 타임스탬프를 수집합니다.【F:ros2_ws/src/draco_roundtrip/draco_roundtrip/nodes/stream_server.py†L1-L160】
- **자동 회귀 벤치마크**: 녹화된 rosbag 재생 시나리오를 구성해 개선 전후 지연을 측정하고, 의사결정에 활용할 대시보드를 생성합니다.
- **적응형 튜닝 컨트롤러**: 실시간 텔레메트리와 SLA 목표를 기반으로 인플라이트 윈도우, 인코더 비트레이트 등을 동적으로 조정하는 제어기를 도입합니다.

### 5. 배포 및 인프라 고려사항
- **컨테이너화된 마이크로서비스**: 실시간 커널 최적화가 적용된 컨테이너로 클라이언트/서버를 패키징해 일관된 네트워킹 스택 구성을 유지합니다.
- **CI/CD 통합**: C++ 노드 빌드, 정적 분석(clang-tidy), 성능 테스트를 자동화해 회귀를 사전에 차단합니다.
- **호환성 계층 제공**: C++ 구성요소로 전환하더라도 기존 파이썬 도구가 동작하도록 어댑터를 제공해 운영 연속성을 보장합니다.

## 다음 단계
1. 이해관계자와 개선 계획을 공유하고 우선순위를 합의합니다.
2. 비동기 파이프라인과 바이너리 프로토콜을 위한 설계 워킹 세션을 진행해 실행 가능한 RFC를 도출합니다.
3. QUIC, 제로-카피 등 핵심 기술의 위험을 줄이기 위해 시간 제한을 둔 스파이크를 계획합니다.
4. 설계 문서가 승인되면 각 개선을 포팅/구현하고, 단계별로 성능 벤치마크를 반복해 지연 감소 효과를 검증합니다.

관련 코드와 테스트는 `../references/codebase_overview.md`에 요약되어 있으며, 진행 상황은 `../checklists/hybrid_architecture_checklist.md`와 동기화하세요.
